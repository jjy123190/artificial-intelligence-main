# 实验四：统一 256 维 ResNet12 对照（2026-11-28）

这里回答的是「在同一套 256 维骨干与固定任务上，监督学习、MAML、分布校准分别怎么样」，不是从历史记录里拼出最高分。三条主线均在 RTX 4050 Laptop GPU 上实际训练与评测，没有使用外部图像或预训练权重。网页、课程报告和 PPT 未在本次实验中改动。

## 固定测试结果

正确率后是该方法自身的任务级 95% 区间半宽（百分点），括号里是答对数，每格分母为 45,000。

| 方案 | 5-way 1-shot | 5-way 5-shot | 两项等权平均 |
| --- | ---: | ---: | ---: |
| 普通监督 CE Baseline | 56.36% ± 0.76（25,362） | 73.18% ± 0.66（32,929） | 64.77% |
| 二阶 MAML（支持集适应 1 步） | 49.86% ± 0.78（22,436） | 62.86% ± 0.75（28,289） | 56.36% |
| 完整校准（单视图） | 67.69% ± 1.15（30,462） | 77.81% ± 0.69（35,016） | 72.75% |
| 去分布对齐（独立 CE 训练） | 67.66% ± 1.15（30,446） | 77.80% ± 0.69（35,010） | 72.73% |
| 去均值校准 | 67.64% ± 1.16（30,436） | 77.75% ± 0.69（34,988） | 72.69% |
| 去方差校准 | 67.58% ± 1.16（30,412） | 77.74% ± 0.69（34,985） | 72.66% |
| 去原型更新 | 58.26% ± 0.82（26,218） | 75.07% ± 0.68（33,782） | 66.67% |
| 去均衡约束 | 65.88% ± 1.05（29,647） | 76.63% ± 0.68（34,485） | 71.26% |
| 完整＋水平翻转双视图 | 67.86% ± 1.17（30,539） | 78.28% ± 0.69（35,224） | 73.07% |
| 完整＋局部匹配 | 68.32% ± 1.08（30,743） | 78.35% ± 0.65（35,257） | 73.33% |
| 完整＋双视图＋局部匹配 | 68.39% ± 1.09（30,774） | 78.84% ± 0.68（35,478） | 73.61% |
| MAML 同权重，不适应支持集 | 19.51% ± 0.53（8,779） | 20.11% ± 0.51（9,049） | 19.81% |

**配对解释。** 下列差值用未四舍五入的逐任务结果计算；括号是任务级配对 95% 区间，单位均为百分点。

- 完整方案相对 CE Baseline 为 **+11.33 / +4.64**（1-shot：+10.56 至 +12.10；5-shot：+4.28 至 +5.00）。前者能利用无标签查询，后者不能；这不是分布对齐训练本身的收益。
- 把原型更新拿掉，完整方案的优势为 **+9.43 / +2.74**（+8.72 至 +10.14；+2.44 至 +3.04）；去掉均衡约束后，差值为 **+1.81 / +1.18**。均衡先验只适用于本协议，不能推广到类别比例未知的任务。
- 训练对齐相对去对齐只多答对 **16 / 6** 个查询，差值 **+0.04 / +0.01**（−0.14 至 +0.21；−0.10 至 +0.12）。均值校准、方差校准的单独配对区间也均跨零。本轮没有足够证据声称这三项分别带来稳定提升。
- MAML 支持集适应比同权重不适应高 **30.35 / 42.76** 个百分点，实际成绩仍低于监督 Baseline。支持集适应起了作用，但在本次训练预算下没有追上 Baseline。
- 预设扩展中，双视图＋局部匹配相对单视图完整方案为 **+0.69 / +1.03**（+0.06 至 +1.33；+0.74 至 +1.31）。这是同一 DA 权重上的扩展结果，不用它替换事先定义的完整方法。

**和旧版的关系。** 旧的 [增强模型＋图像局部匹配](../../outputs/lab04_gpu_regional/results.json) 为 **74.37% / 82.64%**，使用不同的训练历程、特征投影、多视图、局部核和原型初始化策略。它与本轮共享测试任务，但不是本轮的 `full`，也不是某个开关的等预算对照。本轮正交测试的「局部匹配」是下述对称最佳块匹配，不是重用了旧局部核的预测。DINOv2 不参与本表。

## 公平比较的边界

- **数据和任务。** 标准 mini-ImageNet 类别互斥的 64/16/20 划分；每类 600 张。训练只用 38,400 张基础类图。固定测试每种 shot 600 个 5-way 任务，每任务各类 1 或 5 张支持图、15 张查询图，即每种 shot 45,000 次分类。不同任务可复用图像。原协议：[数据清单](../../outputs/lab04/dataset_manifest.json)、[验证任务](../../outputs/lab04/continued_validation_tasks.jsonl)、[测试任务原始 ID／标签](../../outputs/lab04/continued_episodes.json)。
- **共有骨干。** 四个阶段通道 `[32,64,128,256]`，每阶段三层 3×3 卷积＋投影短接，BatchNorm2d、LeakyReLU、最大池化；末层全局均值得到 256 维。所有主方法以同样的单视图 84×84 RGB 原图评测，像素除以 255，按 `(.485,.456,.406) / (.229,.224,.225)` 作均值/标准差归一化，BN 均使用基础类训练的运行统计量。扩展对照只额外引入水平翻转或块匹配。
- **支持与查询的分工。** 分类器只接收像素／特征和支持标签，类别号按支持集首次出现顺序映射为 0–4。Baseline 和 MAML 的单张查询预测不依赖其他查询；完整校准可以联合利用同一任务的**无标签**查询、以及设计已知的类均衡先验。验证和测试查询真值仅传给评分；没有按真值调整原型或按测试成绩选择超参数。MAML 的**基础类训练**任务与此不同：外循环必须用其训练查询标签计算梯度。
- 每行是同一训练种子。置信区间和配对差按 **600 个任务**计算，而不是把 45,000 张查询当作独立图像。它们不包含重训种子的不确定性；这套公开测试任务还有过历史使用，不能视为全新的盲测。

## 三种训练及验证选型

1. **CE Baseline 和去对齐的真实训练对照。** 随机种子 `20261128`。前 8 轮为共享的纯 CE；从第 8 轮的**同一套权重和 AdamW 状态**分叉。两支各续训 12 轮（各 20 轮等效训练），每轮全部 38,400 张原图走一次，300 个更新步。每批 16 类×8 张，另取其中 32 张作独立第二次增强；两支对完全相同的 160 个视图都计算 CE（标签平滑 0.05）。裁剪、翻转、颜色增益、随机种子、样本顺序、分辨率、优化器和学习率均对齐。CE 支的对齐权重为 0；DA 支后 12 轮为 0.75，对成对视图的 L2 归一化特征乘以 √256 后计算批均值及逐维方差的均方差。没有元任务辅助损失。AdamW 权重衰减 0.025，余弦学习率加两轮预热；训练输入依次为 48/64/80，精确逐轮学习率在[训练配置](../../outputs/lab04_unified256/training_plan.json)。两支均**固定取第 20 轮**，不各自挑分。两份[CE 日志](../../outputs/lab04_unified256/ce_history.json)／[DA 日志](../../outputs/lab04_unified256/da_history.json)包含样本顺序指纹、CE、对齐统计量、损失与耗时。
2. **二阶 MAML。** 用上述纯 CE 第 20 轮编码器热启动，换成新初始化的五分类线性头，而不是把 CE 头或原型分类伪装成 MAML。仅用基础类额外元训练 6 轮×64 个任务＝384 个任务、192 次外循环更新；1-shot 和 5-shot 交替，训练查询每类 5 张，训练输入 64×64。每个任务用支持 CE 对**全部可训练参数**（包括卷积、BN 仿射项、五类头）作 1 步 SGD，内学习率 0.06。训练对该步求二阶梯度，以查询 CE 驱动 AdamW 外循环。BN 的运行均值和方差冻结，不在支持或查询批次间传递。验证预先只比较第 3、6 轮，每种 shot 取前 60 个固定验证任务；两项正确数相加为 **4,561 / 9,000** 和 **4,969 / 9,000**，故锁定第 6 轮。此预算低于完整测试；MAML 又比纯 CE 多了元训练，不能宣称是等算力对比。正式测试每个任务都从同一个已选初始化重新适应，只用支持标签，不保留前一任务的更新。逐任务记录首层卷积和分类头的改变量，并另存同权重「适应 0 步」对照。[元训练日志](../../outputs/lab04_unified256/maml_history.json)
3. **均值方差校准＋原型自适应。** 在各自编码器上独立编码全部训练图，拟合训练特征中心与 64 个基础类的均值、逐维方差；**不用测试集估计先验**。先把单位特征减去训练中心并再单位化。Baseline 只用支持集的余弦最近原型；完整方案按支持原型找 3 个最近基础类，以其均值收缩支持原型。逐维方差用 4 个先验自由度与支持方差合并，再向基础类共享标量方差收缩；1-shot 没有可估的类内自由度，靠先验。按加权平方距离给查询软分配，支持原型作锚，用未标记查询更新 8 次。均衡开关独立控制软分配（含最后一步）的 40 轮 Sinkhorn 归一化，它约束**软质量**而非强制最终 argmax 各类恰好 15 张。用全部 600 个验证任务/shot 比较预设的 3 组参数，按两项总正确数选一组：63,782、63,722、63,623（各 / 90,000）。锁定的均值收缩权重为 0.10、方差混合权重 0.20、温度 0.12；所有消融及两种 shot 共享，未单独重调。[评估配置](../../outputs/lab04_unified256/evaluation_plan.json) · [测试前选择记录与权重 SHA-256](../../outputs/lab04_unified256/validation_lock.json)

**怎样读消融和扩展。** `no_alignment` 用真正的纯 CE 权重，用其自身训练类别特征重新拟合先验；推理算法与完整方案相同。`no_mean` 只去支持原型的均值收缩（所有方法共同的训练集特征中心化保留）；`no_variance` 只把逐维方差换为共享标量；`no_update` 的原型不动，但最终均衡分配照做；`no_balance` 改用逐查询 softmax，仍更新原型。多视图、局部匹配另作同一 DA 权重的 2×2 对照，不计入正式完整方案：翻转组对原图及水平翻转的 GAP 求平均，重拟合该视图的训练先验；局部组取第三个残差块 3×3 池化描述子，用查询和支持图之间的对称最佳块余弦分数，按支持类别汇总、标准化后以 0.15 加到全局校准 logits（温度与每次原型赋值之前）。组合组先把翻转后的空间位置翻回，再平均描述子。两模块都不用查询标签，也不重新训练。

从仓库根目录进入 `源码`，以下命令不依赖个人绝对路径。第一段**只需 Python 3.10+ 标准库**，无需 GPU、下载数据或安装 PyTorch，即可由原任务标签和预测重算全部结果（包括验证选型与配对区间）：

```powershell
cd 源码
python -m experiments.lab04.unified256_audit
```

在 NVIDIA GPU 上**从图像重放**，推荐本次实测环境：Python 3.10.19、PyTorch 2.7.1+cu118、NumPy 1.24.3、Pillow 12.1.1、SciPy 1.10.1，Windows RTX 4050 Laptop 6 GB。不同软硬件的浮点细节可能影响临界样本；审计可以逐个比较预测。以下从 `源码` 运行；已有数据的机器跳过 `prepare_data`（默认验证与使用 `.local/mini-imagenet/archives` 中的三个 tar）。

```powershell
python -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu118
python -m pip install numpy==1.24.3 pillow==12.1.1 scipy==1.10.1
python -m experiments.lab04.prepare_data --root .local/mini-imagenet
python -m experiments.lab04.unified256_eval test --output .local/unified256-replay
python -m experiments.lab04.unified256_audit --predictions .local/unified256-replay --compare outputs/lab04_unified256
```
