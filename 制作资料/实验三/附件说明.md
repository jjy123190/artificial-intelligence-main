## 真实性与边界

- 主基准为45图405题；报告对原test/OOD的162题汇总3,888次运行，保留所有成功与失败，不删除坏结果。
- 原test/OOD已经历多轮迭代查看，报告不把这些回归对照重新称为首次盲测；冻结后的新图确认另列。
- GA曲线按实际数据绘制，接近直线及OOD退化均保留；没有为满足预期伪造增长。
- 本地Qwen评估来自现存真实推断记录，本轮没有重新调用模型。原始LLM、训练图拟合的隐藏表示分类头、人为注入错误评分分别标明。
- 原始自由解释未认证与真实语义幻觉不是同一指标；报告不把3/3未认证自动当成3/3语义错误。
- `raw/` 逐字节复制原记录；历史描述和实体名称未篡改。图表与报告明确数据构造和适用范围，不声称真实企业业务准确率。
- `code_audit_20261113.json` 是既有代码审查记录；本次材料复核另见 `delivery_validation.json`，二者不混称。
- 本轮不修改网站、搜索算法或原 `outputs/lab03`；没有生成PPT、演示视频或配音。

## 只读复核

在项目根目录运行：

```powershell
python -B -X utf8 deliverables/lab3/reproduce/verify_delivery.py
```

它会重放15个案例、用独立字典遍历核验答案、重汇总3,888行结果和18个配对区间、核对DOCX数表与PDF文字、检查图文及文件指纹，只更新材料自己的验收JSON。不重新训练，也不调用LLM。默认还会核对交付校验清单，缺失、增加或改变清单保护的文件都会报错。

离线图片索引的独立浏览器复核（需Playwright与本地Chrome或Chromium）：

```powershell
python -B -X utf8 deliverables/lab3/reproduce/verify_gallery.py
```

它在断网模式及禁用页面JavaScript的环境中，检查桌面1366px和手机390px宽度、18张图片、全部138处本地引用以及原生锚点导航；另核对18幅SVG文字边界。不打开项目网站。

完整历史算法证据核验（需原归档齐全）：

```powershell
python -B -X utf8 -m experiments.lab03.verification
```

## 重新排版本报告

先备份当前 `lab3` 目录，避免覆盖你之后的人工编辑。以下顺序只生成材料，不运行旧报告/PPT入口：

```powershell
python -B -X utf8 deliverables/lab3/reproduce/prepare_evidence.py
python -B -X utf8 deliverables/lab3/reproduce/build_figures.py
python -B -X utf8 deliverables/lab3/reproduce/render_diagrams.py
python -B -X utf8 deliverables/lab3/reproduce/build_report.py
python -B -X utf8 deliverables/lab3/reproduce/export_pdf.py
python -B -X utf8 deliverables/lab3/reproduce/build_gallery.py
python -B -X utf8 deliverables/lab3/reproduce/verify_gallery.py
# 下面显式进入已修改文件的复核；仍检查数据/核心文件/统计/轨迹，并不直接接受旧清单：
python -B -X utf8 deliverables/lab3/reproduce/verify_delivery.py --review-updated-files
# 确认上述复核通过且改动符合预期，再创建/更新校验清单：
python -B -X utf8 deliverables/lab3/reproduce/seal_delivery.py --refresh-reviewed
python -B -X utf8 deliverables/lab3/reproduce/verify_delivery.py
```

排版环境使用python-docx、Matplotlib、Pillow；PDF导出使用Windows本机Word及pywin32，预览用PyMuPDF。PNG渲染优先使用已安装diagram技能脚本，缺少技能时回退本地Playwright浏览器。若重生成文件，旧SHA-256清单自然不再匹配；应按上面步骤显式复核并更新清单，不应忽略完整性错误。校验清单覆盖报告、图片、证据、脚本及最初的项目保护清单；自身、可刷新的验收JSON、排版预览与缓存不参与循环散列。`seal_delivery.py`会拒绝接纳复核之后再次被改动的文件；它不修改原始结果，也不能替代人工内容审阅。
